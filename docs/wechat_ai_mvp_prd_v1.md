# AI微信公众号内容生成与排版系统

**第一版 MVP 产品需求文档（PRD v1.0）**  
**日期：2026-11-03｜产品形态：桌面端 Web 应用｜状态：开发需求基线**

**一句话目标：**用户提供主题和素材，AI生成或保留文章正文；系统从40套原创模板中推荐3套，用户可编辑、切换并在仿公众号的手机视图中预览，最后一键复制可粘贴到微信公众号后台的富文本。

## 1. 第一版范围

### 1.1 必须交付的六项功能

| 编号 | MVP 功能 | 交付要求 |
|---|---|---|
| M01 | 输入素材和创作要求 | 支持粘贴文字、输入主题、上传常见文档和图片 |
| M02 | AI生成或保留原文，并支持修改 | 提供“素材创作 / 素材润色 / 原文排版”三种模式；文章可编辑 |
| M03 | 内置40套高质量模板 | 40套实装、可切换、可预览的原创模板，而非40张静态示意图 |
| M04 | AI推荐3套匹配模板 | 生成内容后推荐3个不同风格系列的模板，可进入全部模板库 |
| M05 | 手机预览与一键切换 | 浏览器内模拟微信公众号文章阅读页；切换模板实时生效 |
| M06 | 复制微信兼容富文本 | 点击复制后可在公众号后台粘贴；保留受支持的常规样式 |

### 1.2 第一版明确支持的样式

- **基础文字与标题：**正文、文章主标题、一级/二级小标题、加粗、文字颜色、对齐、字号、行距、段距。
- **边框：**单侧边线、四边边框、圆角边框、边框标题框，使用常规边框CSS。
- **常规图文卡片：**图片＋文字说明、图片＋标题＋简介、上图下文卡片，移动端以单列呈现。
- **背景色块：**章节底色、重点提示框、正文信息块、卡片底色，均为静态纯色。

**不支持：**SVG动画、渐变和复杂特效、JavaScript交互、视频播放器、浮动多列排版、第三方网页整页抓取、自动群发/发布、公众号草稿箱API同步、AI自动配图、协作/权限/付费系统。第一版不得直接复制135编辑器模板资产。

## 2. 用户流程与页面

### 2.1 主流程

1. 用户进入“新建文章”，输入主题或正文，上传资料，选择模式、字数与语气。
2. 点击“生成文章”或“开始排版”；系统提取资料并生成结构化文章。
3. 用户检查并修改标题、段落、图片和小标题；系统自动保存当前浏览器中的编辑状态。
4. 系统默认展示3套推荐模板；用户可点“全部40套”进行分类筛选和切换。
5. 右侧以手机样式实时预览整篇文章；切换模板不改正文。
6. 点击“复制到公众号”；系统写入HTML富文本剪贴板，提示用户去公众号后台粘贴并核对图片。

### 2.2 页面结构

| 页面 | 主要区域 | 关键操作 |
|---|---|---|
| P01 创作页 | 素材区、主题/要求区、模式选择 | 上传、粘贴、设置、生成 |
| P02 编辑排版页 | 左：内容编辑；中：手机预览；右：推荐/全部模板 | 改文、换图、切模板、复制 |
| P03 模板选择弹层 | 分类、40套模板缩略图、3套推荐 | 搜索/筛选、选择、取消 |
| P04 复制反馈弹层 | 复制结果、粘贴步骤、图片检查提示 | 重新复制、关闭 |

无需单独开发复杂的135式拖拽画布。所有文章编辑均围绕标题和内容块进行，降低MVP成本和兼容风险。

## 3. 输入素材与AI内容生成

### 3.1 输入规则（FR-01）

| 项目 | 第一版规则 |
|---|---|
| 文本输入 | 可粘贴全文；单篇合计不超过30,000个汉字或同等文本量 |
| 主题输入 | 允许只输入主题生成文章；主题至少5个字符 |
| 文档上传 | `.docx`、`.pdf`（可提取文本）、`.txt`、`.md`；每次最多5个文件、单个≤20MB |
| 图片上传 | `.jpg`、`.jpeg`、`.png`、`.webp`；最多10张、单张≤10MB |
| 图片用途 | 作为文章插图，用户可决定插入位置；不自动生成新的图片 |
| 不支持情况 | 扫描版PDF、加密文件、无法提取文字的文档，需提示用户粘贴文字 |

**校验：**主题和正文/素材至少提供一项；没有内容时不可提交。上传失败仅影响对应文件，不清空其他输入。系统展示提取后的文本片段，避免把空白或乱码送入AI。

### 3.2 三种创作模式（FR-02）

| 模式 | 具体行为 | 内容保护 |
|---|---|---|
| 素材创作 | 根据主题和素材组织大纲、撰写文章 | 不凭空增加具体数字、引述、人物、机构和事件 |
| 素材润色 | 保留素材事实，改善标题、结构和措辞 | 数值、日期、专有名词、原始引述不得擅自变更 |
| 原文排版 | 使用用户已定稿文本，不调用改写生成正文 | 正文字符内容原样保留；仅识别标题/段落/卡片结构 |

**通用设置：**文章语气（正式/通俗/活泼）、目标长度（约600/1000/1500/2000字）；原文排版模式忽略长度设置。若输入全文本身超过目标长度，AI写作模式应提醒可能压缩原始信息。

### 3.3 AI输出（FR-03）

- 输出文章主标题、摘要（供编辑参考）、按顺序排列的内容块：标题、正文段落、图片、提示卡片。
- AI输出必须是符合预定义Schema的结构化JSON；不允许模型直接生成作为最终产品交付的任意HTML/CSS。
- 文章事实以用户素材为依据。缺少可信资料时使用中性表达或标记“待核实”，不得虚构精确数据和引用。
- 生成失败可重试；最多自动重试1次，再提示用户手动重试。禁止失败后覆盖已生成或已编辑文章。
- 用户可在确认内容后点击“重新生成”，必须二次确认，因为该操作可能替换正文；换模板不触发重新生成。

## 4. 正文编辑（FR-04）

### 4.1 必需操作

- 直接修改文章主标题、摘要、正文、小标题、图片说明。
- 内容块可新增、删除、上移、下移；可切换“正文段落 / 一级标题 / 二级标题 / 提示框”。
- 文本支持加粗与文字重点色；标题及正文具体视觉格式由模板控制，不要求自由设置任意CSS。
- 图片可插入到任一内容块之间、替换、删除，并可编辑说明文字；图片显示应保持原始宽高比。
- 实时预览随编辑更新；更换模板不得清除编辑内容。
- 自动保存到当前浏览器（文字与必要的图片引用/数据）；页面意外刷新后恢复最近一次编辑。需提示“清理浏览器数据或更换设备可能丢失本地草稿”。

### 4.2 内容与样式必须分开

文章只存标题、正文块和图片引用；排版由`templateId`和配置决定。编辑正文不会修改模板定义，切换模板不会改变正文字符和内容块顺序。

## 5. 模板系统与推荐（FR-05）

### 5.1 模板功能规则

- 模板库固定交付40套可使用的**原创完整模板**，每套有唯一ID、名称、适用行业、风格标签、预览缩略图、统一样式配置。
- 一套完整模板必须覆盖：文章主标题、一级/二级标题、正文、边框提示块、纯色背景块、单图及图文卡片。即使文章没有某种模块，模板也必须定义其样式。
- 40套不是“1个结构换40种颜色”；每套相较同类模板应至少在**两个版式维度**存在实质区别，如标题构图、章节标记、边框构造、图文卡片布局、留白节奏。
- 首次生成后推荐3套，来自3个不同风格子类；用户可一键切换，或进入全部模板库按行业/风格筛选。
- 推荐优先使用内容类型、篇幅、图片数量、标题层级和模板标签评分。可以由规则引擎完成基础推荐，AI负责推荐说明，不必调用AI生成排版代码。
- 每次模板切换只改变视觉，不重排段落顺序、不删除图文、不再次调用文章生成模型。

### 5.3 模板质量标准

- 每套至少提供：真实文章完整预览（非空白模板）、缩略图、配置数据、对应CSS渲染规则。
- 所有模板在320px、375px、414px内容宽度下无横向溢出、无遮挡、无不可读文本。
- 统一适配短文、长文、含图片文章；标题超长自动换行，图片按容器宽度缩放。
- 模板不得依赖外部字体、JS、SVG动画、渐变和公众号可能过滤的复杂布局才能呈现主体效果。

## 6. 手机预览（FR-06）

- 页面中提供宽度约375 CSS 像素的手机阅读区域，展示仿微信公众号的顶部导航、文章标题、正文内容、图片与滚动效果。
- 顶部导航仅是**视觉模拟**；不要求完全还原微信每个版本的真实界面。
- 模板切换或正文改动后，预览立即更新。预览主体与最终复制HTML使用同一个渲染器，避免两套代码效果不一致。
- 图片加载失败显示占位和更换入口，不得静默消失。超长文章可在预览区域内独立滚动。
- 预览区可切换“手机宽度/宽屏阅读检查”，但默认展示手机视图；无需真实微信客户端远程预览。

## 7. 微信富文本复制（FR-07）

### 7.1 实现规则

1. 从文章JSON与选中的模板生成**语义简单、CSS内联**的HTML；只允许已测试通过的常规HTML标签和CSS属性。
2. 所有用户文本要转义，清除脚本、事件属性、不安全URL和外部样式表；不得把AI返回的HTML直接插入剪贴板。
3. 用户点击按钮时通过浏览器`navigator.clipboard.write()`写入`text/html`和`text/plain`两种表示；功能要求HTTPS环境并处理权限失败。
4. 写入成功提示“富文本已复制，请在公众号后台粘贴，并检查图片”；剪贴板成功不等于微信公众号粘贴已经成功。
5. 不支持富文本写入的浏览器提示使用Chrome/Edge桌面版；可以提供纯文本备选，但必须明确纯文本不保留排版。
6. 图片处理需做真实微信公众号粘贴验证；网络图片可能被重写或失效。若当前环境不能保证图片保留，明确标记需手动补图，提供原图查看/下载入口，不得无提示丢图或声称无损复制。

### 7.2 兼容性目标

| 模块 | 必须保留的效果 | 不承诺的效果 |
|---|---|---|
| 基础文字/标题 | 文本内容、加粗、常规大小、颜色、层级 | 完全一致的系统字体字形 |
| 边框 | 边线、边框内边距及基本圆角（若微信保留） | 高级阴影、复杂装饰 |
| 背景色块 | 静态纯色底与块内文本顺序 | 渐变、透明叠加特效 |
| 图文卡片 | 图片/标题/说明的单列顺序和边框结构 | 外部图片100%自动转为微信素材 |

**正式上线门槛：**必须在真实公众号后台完成“复制 → 粘贴 → 保存草稿 → 重新打开”测试，不得只通过浏览器预览判定兼容。

## 8. 数据模型与建议接口

```json
  "summary": "文章摘要",

    {"id": "b2", "type": "paragraph", "text": "正文段落"},
    {"id": "b3", "type": "imageCard", "assetId": "img_01", "caption": "图片说明"},
    {"id": "b4", "type": "callout", "text": "重点提示"}
  ],
  "templateId": "T06",
  "updatedAt": "2026-11-03T00:00:00Z"
}
```

正文块只存内容与类型；`templateId`只决定展示样式。后端至少校验字段、长度、资源地址和允许的内容块类型。

### 8.2 建议服务接口

| 接口 | 作用 | 返回 |
|---|---|---|
| `POST /api/materials/parse` | 提取文件文字、图片元信息 | 结构化素材/错误说明 |
| `POST /api/articles/generate` | 按模式生成文章 | 符合Schema的文章JSON |
| `GET /api/templates` | 读取40套模板与标签 | 模板列表、缩略图和配置版本 |
| `POST /api/templates/recommend` | 根据文章特征推荐3套 | 3个不同风格的模板ID |
| `POST /api/assets` | 接收并校验用户图片 | 图片ID与可预览地址 |
| `POST /api/render/wechat` | 将文章与模板转换为安全HTML | HTML、纯文本、资源清单 |

接口命名为建议，不强制技术栈。推荐与渲染也可放在前端，只要输出、性能和安全要求一致。

## 9. 异常、隐私与基础质量

| 场景 | 产品必须采取的行为 |
|---|---|
| 用户没有输入 | 禁用生成并提示“请输入主题或上传/粘贴素材” |
| 扫描PDF无法提取文字 | 显示“无法读取文本，请粘贴文字”；不把空文档送AI |
| AI生成超时或失败 | 保留输入和已编辑内容，给重试按钮与具体错误 |
| 图片尺寸超限/损坏 | 拒绝该图片且保留其他资料；提示限制 |
| 网络中断 | 当前可编辑内容仍保留本地，联网后可重新生成 |
| 粘贴权限被拒绝 | 明确说明未复制成功，提供浏览器建议或纯文本备用 |
| 内容超长或模板不兼容 | 自动换行/单列降级；禁止横向溢出和文字遮挡 |
| 用户切换模板 | 保留所有文字、图片顺序和人工修改 |

**安全与隐私底线：**AI密钥只能放服务端；上传文件要做类型/体积校验；防XSS/HTML注入；服务端限制调用频率；向用户明确告知素材可能提交给AI服务处理；不得未经授权使用第三方模板、图片、字体资产。原文模式必须有文本一致性检测。正式部署前确定素材存储期限、用户删除机制和AI生成内容标识/审核规则。

### 10.2 模板批量测试要求

- **40套×3篇标准测试文章×3种宽度**进行自动截图对比；标准文章分别为纯文字长文、标题层级较多文章、含图片与背景卡片文章。
- 所有40套模板至少各在Chrome桌面版、Edge桌面版进行一次真实公众号粘贴回归；涉及图文卡片的模板必须检查图片显示。
- 发现文字丢失、背景字色冲突、标题遮挡、卡片溢出、复制失败等问题时，相关模板不得标记为“可用”。

### 10.3 性能目标（开发期验证、可据实调整）

- 40套模板目录首次加载目标≤3秒（普通宽带、已优化静态资源）；缩略图懒加载。
- 在2000字以内、含5张图片的文章中，切换模板后的本地预览目标≤1秒。
- AI生成的等待进度、失败提示和重试功能必须完整；不承诺固定秒数，监控实际延迟与失败率。
